# Сайт colibrikids.ru: как устроен и как выкладывать изменения

## Коротко

- **git — только хранилище кода.** Репозиторий `github.com/dan-rusakov/colibri`, рабочая ветка `develop`. Сервер с git никак не связан: ни `git pull`, ни автодеплоя нет.
- **На сервер файлы заливаются руками** через админку WordPress → плагин Advanced File Manager. SSH-доступа нет.
- Раньше (до декабря 2020) тема на сервере была клоном репозитория и обновлялась через SSH командой `git pull`. **Эта схема больше не используется.**
- **На 27.09.2026 git и прод синхронизированы:** PHP-файлы темы совпадают с `develop`, а `dist/`, собранный из `develop`, побайтово совпадает с тем, что лежит на сервере.
- `master` — заброшенная ветка с двумя коммитами 2020 года, не используется.

## Как устроен сайт

- https://colibrikids.ru, WordPress 5.5.22.
- Тема: `wp-content/themes/colibri` (активна, дочерней темы нет).
- Фронтенд — Vue-приложение. WordPress отдаёт пустую страницу из `index.php`, а Vue подгружает контент через REST API.
- **Контент хранится в базе WordPress, не в git.** Это страницы со slug `main-page`, `about`, `schedule`, `documents` и их поля ACF. Vue ищет страницы по slug, поэтому slug нельзя менять, а страницы нельзя удалять.
- Плагины, от которых зависит тема: Advanced Custom Fields (поля страниц) и ACF to REST API (отдаёт поля по `/wp-json/acf/v3/`).
- Структура полей ACF выгружена в `Colibri Tools Export Mar 17 2025.json` (ACF → Инструменты → Экспорт). Если меняете группы полей в админке, выгрузите заново и закоммитьте.
- Форма заявки отправляет запрос на `/wp-json/api/feedback` (обработчик в `functions.php`), и тот шлёт письмо на kolibrigym@gmail.com.
- Пользователь `manager` видит в админке урезанное меню (`hide_menu_items` в `functions.php`).

## Что из репозитория нужно на сервере

| Файлы | На сервере |
|---|---|
| `functions.php`, `header.php`, `footer.php`, `index.php`, `style.css`, `screenshot.jpg` | нужны |
| `favicons/` | нужна |
| `dist/` | нужна; собирается командой `npm run build`, в git не хранится (`.gitignore`) |
| `src/`, `webpack/`, `package.json`, `package-lock.json`, `.nvmrc`, `DEPLOY.md`, `README.md`, экспорт ACF | не нужны, это только для разработки |

**Внимание:** в папке темы на сервере сейчас лежат ещё `src/`, `node_modules/` (~360 МБ), `.git/`, `webpack/`, `package.json` и т. п. Это остатки старой SSH-схемы в состоянии на декабрь 2020 (коммит `77e20a7`, `.git` смотрит на старый репозиторий `dan3439/colibri`). Сайт их не использует. **Не берите оттуда код и не ориентируйтесь на них:** актуальный код — только в git.

## Сборка

```sh
nvm use            # Node 16.20.2 из .nvmrc
npm ci
npm run rmdist     # удалить старый dist, чтобы не копились файлы прошлых сборок
npm run build
```

- Нужна именно Node 16.20.2: на ней собран текущий прод. С этой версией и `package-lock.json` сборка побайтово совпадает с продом (проверено 27.09.2026 чистой установкой через `npm ci`).
- Предупреждения `DEPRECATION WARNING` от Sass — это нормально, на результат не влияют.
- `npm run watch` делает dev-сборку для работы с локальным WordPress. Она несжатая (~1,7 МБ) и содержит исходники, **на прод её не выкладывать.**

## Выкладка на прод

1. Закоммитьте изменения в `develop`.
2. Соберите проект (см. «Сборка»).
3. **Сделайте бэкап:** в File Manager откройте `wp-content/themes/colibri` и скачайте папку zip-архивом к себе на компьютер. Если архив создавался на сервере, удалите его оттуда: всё, что лежит в папке темы, можно скачать по прямой ссылке.
4. Залейте изменённые файлы: PHP — в корень темы, содержимое `dist/` — в `dist/` с заменой. Любой временный zip, загруженный на сервер для распаковки, после распаковки удалите.
5. Если менялся JS, сбросьте кеш `index.js` (см. «Известные проблемы», пункт 1). `styles.css` обновится сам: его версия берётся из даты файла.
6. Откройте сайт в режиме инкогнито и проверьте все страницы: главную, «О нас», «Расписание», «Документы». Отправка формы шлёт настоящее письмо.
7. Запушьте `develop` и добавьте строку в журнал выкладок ниже.

**Правило:** не править файлы прямо на сервере (редактором File Manager или «Редактором файлов темы» в WordPress). Если что-то пришлось срочно поправить на сервере, сразу перенесите ту же правку в git, иначе git и прод снова разъедутся.

## Как проверить, что прод и git совпадают

1. Скачайте папку темы через File Manager и распакуйте, например в `~/Downloads/colibri`.
2. Сравните PHP и статику:
   ```sh
   for f in functions.php header.php footer.php index.php style.css screenshot.jpg; do
     cmp -s "$f" ~/Downloads/colibri/"$f" || echo "DIFF $f"
   done
   diff -rq favicons ~/Downloads/colibri/favicons
   ```
3. Соберите проект (см. «Сборка») и сравните `dist/`:
   ```sh
   diff -rq dist ~/Downloads/colibri/dist
   ```
   Все файлы из свежей сборки должны совпасть побайтово. Строки `Only in .../Downloads/colibri/dist` — это остатки старых сборок на сервере (см. «Известные проблемы», пункт 2), а не расхождение.

## Известные проблемы

1. **Сброс кеша `index.js` не работает автоматически.** В `functions.php` на сервере 17.03.2025 руками дописали `?v2`:
   ```php
   get_stylesheet_directory_uri() . '/dist/scripts/index.js?v2',
   filemtime( get_stylesheet_directory() . '/dist/scripts/index.js?v2' ),
   ```
   Файла `index.js?v2` не существует, поэтому `filemtime` на каждой загрузке страницы пишет PHP warning и возвращает false, и WordPress подставляет в ссылку свою версию (`index.js?v2&ver=5.5.22`). В итоге браузеры не узнают о новом `index.js`, пока руками не поменяют `v2`.
   - **Пока не исправлено:** при каждой выкладке нового JS меняйте `v2` на `v3`, `v4` и т. д. в первой строке.
   - **Исправление:** вернуть в обеих строках `'/dist/scripts/index.js'` без `?v2` и выложить `functions.php`. Тогда версия будет браться из даты файла, как у `styles.css`.
2. **Мусор в `dist/` на сервере:** `3.styles.css`, `vendors~about.styles.css`, `vendors~schedule.styles.css`, `scripts/vendors~about.js`, `scripts/vendors~about~documents.js`. Это остатки прошлых сборок, текущий `index.js` их не загружает. Можно удалить через File Manager.
3. **Остатки SSH-схемы в папке темы на сервере** (`src/`, `node_modules/`, `.git/`, `webpack/`, `package*.json`, `README.md`). Сайт их не использует; `src/` и `package.json` открываются по прямой ссылке (`.git/` закрыт, отдаёт 403). Можно удалить после бэкапа, чтобы не путаться.
